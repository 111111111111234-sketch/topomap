以下按设计阶段描述的内容保留作为方法规格，不代表新增实现已经通过验证。

## 1. 方法目标与证据边界

以 HGR 的感知、假设推理、目标匹配与局部执行为基础，建立跨子任务持久空间层，
在相同 Place 身份上维护当前目标的动态状态；两层共同决定目的地、全局路线和执行反馈。
Topo 是全局导航主地图，度量地图是碰撞检查和局部轨迹底座，二者共享实际目的地和路线。
不是只在提示里附加路线，也不是要求机器人逐一停在 Place 中心。

拟验证的收益为长程路线质量与同场景经验复用，不预设一定提高 SR、SPL 或速度。
当前融合 smoke SR 6/8→7/8，但路径 39.37→63.73m、时间 19:25→28:12，
不足以认定收益。任务 0 的选择分岔、任务 3/5 的拍摄 Place 折返、后续任务起点差异
须分别处理，不能统一解释为节点过密。

参考方案的取舍：

| 建议 | 本版决定与理由 |
| --- | --- |
| 持久空间层＋目标动态覆盖层 | 采用；共用 Place ID、对象身份与执行状态 |
| transition 指导连续局部运动 | 采用；先修正确终端，再移除必须到达历史 anchor 的依赖 |
| 新增每个对象的 VLM Verify | 本轮不采用；会改变 HGR 确认/停止条件，并重现 Phase C 调用循环 |
| doorway/junction 作为新节点 | 后置；先保留 B-R5 节点身份和尺度，避免混入采样消融 |
| corridor 偏离软代价 | 不能单独作为认证；实际路径必须满足已知自由空间与有序 transition |
| 局部可达就绕过 topo | 改为统一路线中的零 transition 特例；不以完整场景 Pathfinder 连通性作证 |
| R3 SR 上升证明高层选择改善 | 不接受；R3 是固定选择的 route-only，历史均值不提供该因果证据 |

## 2. 一套闭环与生命周期

```text
HGR RGB-D / objects / snapshots / frontiers / hypotheses
                         ↓ 增量更新
L1 SceneMemory：Place、认证连通、稳定对象、多视角证据、approach
                         ↕ 同一 Place / entity ID
L2 GoalState：当前目标证据引用、搜索覆盖、候选、active intent
                         ↓
原 HGR selector：原视觉/假设 + L2 状态 + L1 完整路线成本
                         ↓ 同一候选/对象身份
RoutePlan：实际位姿 connector + transitions + 真实终端段
                         ↓
HGR local executor：沿认证 guidance 连续闭环执行
                         ↓
Feedback：感知更新 L1；目标/搜索事件更新 L2；原终端协议判断结束
```

L1 在同一 episode 的子任务间保留；episode 结束清空。跨 episode 磁盘地图复用先不实现，
除非显式提供稳定坐标/地图身份和重定位契约，不能仅凭 scene ID 拼接。
L2 每个新目标重新投影，复用客观 RGB、对象、几何和有效路径；上一目标的否定结论不迁移。
原 HGR 也保留历史 Snapshot，因此必须测量 topo 在已有记忆之上的增益。

## 3. 第一优先级：统一对象身份、目的地和路线成本

保留四个独立含义：`observed_from_place_ids`、不可变 `capture_pose`、
可更新 `approach_place_id`、`terminal_observation_pose`。Snapshot 是证据来源，
不能直接把 capture Place 填成对象路线目的地。

建议先增加纯几何 `ApproachResolver`：输入真实选中 object/source、当前已知地图和位姿，
输出当前 HGR 对该对象要执行的安全终端及合法接近路线。优先将现有 HGR 终端生成逻辑
抽成可查询、无执行副作用的接口；不得为每个对象新建一套环形验证搜索。
现有函数若依赖完整 Pathfinder，需要将该依赖隔离为历史对照，新增认证路径只用已知空间。
目标身份与成功/停止标准保持固定；终端几何修正作为明确的执行变化单独报告。

| 数据 | 契约 |
| --- | --- |
| ApproachResult | entity_id、source evidence、terminal pose/look-at、可用 approach 集合、几何版本、状态/原因 |
| RoutePlan | 起始实际位姿、connector、有效 transition、终端段、各段长度、总长度、相关版本 |
| Candidate | 原 HGR 稳定 source/object/frontier ID、证据、当前目标状态、RoutePlan 引用 |

路线评分使用一条连续认证路径的总长度，connector、图内段、terminal 各计一次。
不得把不同 anchor 基准的距离相加，也不得只显示图边和而省略对象终端成本。
多接近点按完整路径比较，不先锁死历史 capture Place。
same-place 可以有非零终端成本；局部直达必须来自已知自由空间认证，且不违背已选 transition。
同一已知连通岛可能覆盖全屋，不能以整岛可达作为无限制“局部”捷径。

原 selector 在 object crop 级选择时，应提供相应对象成本；只知道 Snapshot 而对象未确定时，
不能用单个拍摄点成本代表全部 crop。筛选后标签重新对齐，未知成本显式 unknown。
选中后以相同 entity 和终端重验证；源合并只重绑定身份，不静默改选对象。
没有合法 approach 返回显式结果，保留可解释的开发期安全回退并计数，不伪造边或终端。

## 4. 连续执行与路线约束

将 `RouteGuidance` 从 `phase_c_enabled` 解耦，让 HGR 已选目标也可安装同一 guidance。
复用已有路径认证、supercover、前视执行与路线进度测试；不能仅取消配置 guard，必须
迁移其 active source、终端朝向、失败恢复和预算结束清理的生命周期。

先使用已认证路径的保守连续前视，保留每步观测/碰撞检查和原动作步长。
Place 只是空间身份；前视点可越过无必要停顿的 anchor，但必须按有序 transition 前进。
硬可行域由已知自由空间和路线约束确定；软代价只能在域内改善平滑度，不能覆盖障碍和未知。
更宽 corridor、portal 几何和优化器后置，不将当前窄路径前视称作已经实现的自由连续优化器。

失败顺序：局部轨迹修复 → 同目标重路由 → 无法恢复后重新选择。
一次控制失败不删除空间边；仅有明确几何证据才使边失效。恢复路径继续使用同一目标。
局部修复、图重路由和高层重选分别记录，terminal 到达才进入原 HGR 结束流程。

## 5. 第二层：将 HGR 状态组织到图上，不另建选择模型

`GoalState` 是持久于当前子任务的状态，不是每次临时生成的 JSON 路线列表。
在 Place 上保存目标证据引用、HGR 假设引用、真实覆盖、未解决候选和 active intent。
HGR 的 semantic hypotheses 作为探索先验，不等于实测对象支持，不能生成可通行边。
不引入额外模型或人工混合 utility；null 表示未评分，不等于负证据或正支持。

原 HGR Snapshot/Object 与 Frontier 继续为外部选择协议；内部仅归一为两类导航意图：
`EXPLORE` 和 `TARGET_APPROACH`。若论文称第二类 Verify，必须说明只是历史证据目标的
导航意图，不能暗指已经启用额外 fresh-VLM 确认。当前原 HGR 终端协议作为独立固定模块。
新的 fresh verification 仅允许后续显式停止协议消融，不能混进本轮性能对照。

原候选、图像尺寸/数量预算、预筛选和提示中的视觉证据保留；先以状态 sidecar 接入原选择器，
再让候选读取统一的 GoalState。第二层回收对象合并、源失效和执行反馈，防止出现两个
互相独立的候选状态机。目标切换与普通感知更新使用不同事件。

覆盖仅由实际观察登记；移动到一个 Place 不等于搜完整个区域。请求/控制错误不作为语义负证据。
若原接口没有语义拒绝结果，就不凭空生成 rejected/uncertain。历史 coverage 八方向仅是近似，
不能把 object center 漂移或任意新 pose 桶当成独立新可见面；该局限必须保留在日志与实验说明。

## 6. 事件驱动与增量复用

分别管理 evidence、geometry 和 intent lifecycle；单个 global revision 只适合缓存标签，
不能决定是否调用高层。保留原 HGR 预先定义、可测试的目标发现/确认触发。

| 事件 | 行为 |
| --- | --- |
| 新目标 | 从已有 L1 投影 L2，调用原 selector |
| 普通 RGB/对象更新 | 增量登记，当前有效 intent 默认续行 |
| waypoint/transition 通过 | 推进路径进度，不调用 selector |
| 真实 frontier 到达/消失、目标源失效、意图完成 | 更新 L2 后重选 |
| 路线受阻 | 先同目标恢复，恢复失败才重选 |
| 原 HGR 即时目标确认事件 | 保留既有优先处理协议，不新增分数抢占阈值 |

`choose_every_step` 的探索重选改为持续意图是策略变化，必须独立配置/消融，不能称为无损缓存。
先修几何并验证原选择频率，再启用该变化。重用 source 时每步检查真实身份和可执行性。
不减少每步感知以制造速度提升，不新增次数上限、类别冷却或对象永久黑名单。

无损缓存仅覆盖相同依赖：图像按像素/crop，路径按相关几何，证据按实体与来源。
无关远端地图更新不使全量失效；相关路径变化必重验。新目标可复用视觉事实和几何，
不得复用旧目标匹配分数或整个模型答复，除非目标与完整请求依赖完全相同。

## 8. 评估如何回答长程与经验复用

先保存选定目标、当前位姿、已知网格、对象/观测身份和地图版本进行同输入重放。
旧日志不够恢复当时已知网格时明确记 unavailable；禁止用未来地图补齐后宣称在线等价。
重放回答实现一致性与路线几何，闭环测试回答成功和成本，二者不可互相替代。

必要对照：当前 HGR baseline、历史融合、V2-A、V2-A+B、完整 V2（C/D），
辅以选择频率与缓存开关配对。所有对照固定观察预算、模型输入规则与停止协议；
若有必要的终端几何变化显式列出，不能宣称逐动作保持原版。

长程以运行前固定的路线距离/跨 transition 分组分析；阈值仅用于报告，不进入策略。
同场景经验使用相同目标/起点、相同后续任务序列，分别从冷地图和允许历史探索所得的暖地图
开始；暖地图构建不得使用完整 GT。保持共同 HGR 历史记忆的有/无 topo 对照，区分
“HGR 原本有记忆”和“topo 新收益”。报告历史探索成本及后续任务摊销成本。
仅按任务序号比较快慢会混入目标难度和上一任务终点，不作为经验收益证据。

报告完整分母与失败任务、SR/SPL、路径、动作、各类 VLM 请求、wall time、源失效、
局部修复/重路由/高层重选。互斥阶段计时区分感知、建图、候选准备、请求和运动；
不能从总时间减 API 后全部归给拓扑。重复闭环运行并按 episode/scene 汇总，
固定 12×2 仍是开发集，未做独立验证前不宣称泛化。

## 9. 下一次可执行修改的范围

先实现 V2-A：选择协议不动，冻结原 HGR 所选对象，把到 capture Place 再折返的路线
换成经过已知合法 approach 的同对象终端路线；提示与执行消费同一个完整成本与终点。
用现有 task 3/5 日志作为诊断线索，增加不依赖这些 scene 的结构回归。
这一步通过后做 V2-B，再接 V2-C，不同时重写选择、停止、节点采样和局部运动。
最终版本的三个待验证能力是持久空间记忆、目标条件状态、连续拓扑导航，
它们是开发目标，不是已经成立的论文结论。
