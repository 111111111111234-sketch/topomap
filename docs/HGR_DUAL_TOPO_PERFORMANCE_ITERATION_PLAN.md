# HGR 双层拓扑性能迭代计划

日期：2026-09-14。

状态：M0–M4 首轮代码已实施，离线测试通过（1 项 CUDA 测试因当前环境无可用 CUDA 而跳过）；在线 simulator 与模型效果待用户运行。实施细节、最新测试数和命令见 [开发实施记录](HGR_DUAL_TOPO_PERFORMANCE_DEVELOPMENT.md)。

实施范围覆盖诊断、缺陷修复、机制拆分和性能评测。开发方执行离线测试并提供运行脚本，在线 simulator 与模型评测由用户启动。

相关材料：[阶段实施报告](HGR_DUAL_TOPO_STAGED_IMPLEMENTATION.md)、[本轮 smoke 结果](HGR_DUAL_TOPO_SMOKE_20260913.md)。

## 一、目标、基线与开发原则

目标是保留 Route-only 已接入的拓扑规划能力，在同一 episode 的多 goal 任务中，提高历史证据复用准确性，减少无效重访、重复请求和错误停止。

本轮依据为 `20260913T123622024858Z` 批次：一个场景、一个 episode、8 个子任务。数据来源为该批次运行汇总、各阶段的 `subtask_metrics.json` 和导航 trace。

| 阶段 | Snapshot SR | Distance SR | Distance SPL（×100） | 总步数 | 模型调用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Baseline | 25.0% | 75.0% | 46.15 | 44 | 87 |
| Shadow | 0.0% | 75.0% | 46.95 | 46 | 83 |
| Known-space | 25.0% | 50.0% | 41.67 | 43 | 71 |
| Route-only | 37.5% | 87.5% | 55.98 | 85 | 127 |
| Memory | 0.0% | 37.5% | 16.78 | 282 | 347 |
| Intent | 12.5% | 62.5% | 21.43 | 279 | 518 |
| Verified | 50.0% | 75.0% | 36.16 | 147 | 355 |

这些结果用于定位问题，不作为性能提升证明。Route-only 的 Distance SR、Distance SPL 和 Snapshot SPL 在本轮最高；Verified 的 Snapshot SR 最高。Route-only 是后续几何执行的候选基线，原版 HGR 继续作为性能对照。

开发遵循以下约束：

- 每次只改变一个可识别的机制，保留关闭该机制的对照。
- 不通过扩大步数、增加模型重试或放宽成功距离掩盖退化。
- 不让目标真值、评测距离或隐藏导航网格参与策略。
- 全局事实跨 goal 保留；当前目标的否定、确认和检查状态按 goal 隔离。
- 旧运行结果保留；修复后的结果使用新配置标识和独立目录。

### 对当前记忆能力的准确界定

Route-only 已有跨 goal 的几何、对象和 Snapshot 记忆；Memory 阶段增加的是显式任务授权与重访调度。因此，不能将 Route-only 描述为“没有跨任务记忆”。

Route-only 中，实际路线执行使用 PlaceTopology 与 TSDF 已知空间。SceneMap 同步场景事实，GoalGraph 按 goal 重建并记录候选；它们在此阶段不会替换原版 HGR 的语义选择。

本轮 trace 显示：第一个 goal 结束后保留 8 Places、100 个实体索引、14 条边；第八个 goal 开始时为 11 Places、135 个实体索引、30 条边，第八个 goal 结束后为 137 个实体索引。实体索引数量不等同于经过独立验证的真实物体数量。

上述记忆默认限定在同一 episode，不代表同场景不同 episode 或进程重启后自动继承。

## 二、分阶段实施内容

### M0：冻结证据，补齐任务结束与失败诊断

目的：区分程序跑完、任务正常结束和导航成功。

冻结本批次的运行汇总、指纹、配置、子任务指标和 trace，生成逐子任务对照，重点标出：

- Memory/Intent 第一个 goal：1 步、0.5 米后结束，距目标约 5.49 米。
- Known-space：4 个 image goal 全部失败。
- Memory/Intent：各一次上层选择失败。
- Intent/Verified：候选解析与探索失败，以及已修复的 critic 设备异常。

在 runner 的结束路径和 logger 的子任务记录接口中增加结构化结果：

| 字段 | 用途 |
| --- | --- |
| `termination_reason` | 记录实际触发结束的原因 |
| `execution_status` | `completed`、`exhausted`、`error`；旧数据为 `unknown` |
| `error_counts` | 分开统计请求、解析、执行及验证错误 |
| `navigation_diagnostics` | 实际 backend、选择来源、任务类型和执行统计 |

结束原因至少覆盖：原版停止、验证确认、步数耗尽、无可执行候选、请求耗尽、解析失败、执行错误和无法恢复。

采用“首次终止原因锁定”，避免退出后清理逻辑覆盖真正原因。预算结束属于正常失败，不标记为内部错误。`completed` 只表示正常完成停止协议，不等于评测成功。

现有 `NoAction`、`RequestError` 必须保留区别。上层收到 `None` 时，不再统一报告“模型请求失败”；未知来源明确记为未分类选择失败。现有日志里的 `query_vlm_for_response failed` 不足以证明模型服务故障。

兼容规则：

- 原有 SR/SPL 字段和汇总口径保持可读。
- `metric_validity` 继续表示数值有效性，另外输出执行质量。
- 性能主表保留全部预定子任务，不删除报错样本来提高均值。GOAT SR 严格要求任务以有效停止完成且终点距离成功；预算耗尽但最终位置恰好在阈值内不计成功。Distance SR/SPL 与 Snapshot SR/SPL 保留为位置和实体关联诊断。
- 错误率、缺失结果和重试另表展示。

完成门槛：每个新运行子任务都有唯一结束原因；缺失原因不能被汇总工具判为验收通过。

### M1：修复可复现缺陷，建立选择与到达契约

首先定位一步结束，不能直接把它判成实现错误。

从 Memory/Intent 的第一个 goal 提取选择的 Snapshot、实体、候选映射、终端坐标、实际位置、任务类型和停止分支，建立固定输入回归。

按证据处理：

- 若选择映射、实体绑定或终端生成错误，修复对应错误。
- 若 HGR 确实选择了错误对象，而原版停止协议正常触发，则记录为语义选择失败；不在 Memory/Intent 中隐式加入 Verified 的停止规则。
- 拓扑中间 waypoint、REVISIT 观察点和最终 APPROACH 终端必须分别处理。
- Verified 只有同一实体的新鲜验证返回 `confirmed` 才能成功停止。

排查 Known-space 的 image 失败：记录目标观测位置、对象 approach 终端、已知空间可达性和最后运动状态，区分错误终端、合理不可达和错误对象选择。

完成 critic 修复验证：

- 保留已有 device/dtype 迁移修复，不将这项已完成修改重复记为新开发成果。
- 补真实张量的精度一致性与可用 CUDA 环境下的设备测试。
- GPU 不可用时明确跳过 CUDA 测试，不把 CPU 测试视为 GPU 验证。
- 特征计算异常在诊断中计数，禁止只打印日志后无痕降级。

排查 `no snapshot is available`：

- Frontier-only 候选集允许原有探索选择。
- 模型返回候选集外编号时记解析错误。
- 无 Snapshot 不等于请求服务异常。
- 重试沿用已有预算，不叠加无限重试。

完成门槛：本轮每类主要异常都有固定输入复现或明确的证据不足说明；已确认缺陷有回归测试。若旧记录不足以确定原因，补观测后由用户重跑，不凭推测修改停止语义。

### M2：明确全局地图、目标图和历史证据的职责

继续使用现有 Scene、TSDF、PlaceTopology 和 SceneMap，不新建重复的场景记忆系统。

全局层跨 goal 保存：

- 已观察空间、Place 节点及经过验证的边。
- 存活对象、对象 alias、历史 Snapshot 与证据来源。
- 证据首次/最近出现的 goal、step 和观察位置。

SceneMap 是事实索引，实际几何规划继续使用 PlaceTopology 与已知空间。历史索引中的实体只有经过存活和来源检查，才能成为可执行候选。

目标层每个新 goal 重建：

- 当前目标候选及证据关联。
- 已检查证据和观察点。
- 当前目标下的确认、拒绝和 unresolved 状态。
- 当前 intent、去重记录和临时失败状态。

统一 navigator 保持以上生命周期一致。旧 goal 对某实体的否定不得直接否定新 goal；对象位置和观测证据仍可以复用。

每次 goal 切换记录全局图规模和目标图初始化状态，验证“保留事实、重建目标状态”实际发生。

完成门槛：三 goal 离线场景证明第二个 goal 可使用第一个 goal 的对象与路线，第三个不同目标不会继承不适用的否定结论。

### M3：逐项收敛 Memory 与 Intent

先建立统一链路的无新增策略对照：使用原版 HGR 候选呈现与选择节奏，加 Route-only 几何执行。再依次开启以下行为：

1. 来源绑定：选择结果绑定具体 Snapshot、实体、证据与终端；对象合并后迁移来源，失效后撤销授权。
2. 重复抑制：已针对当前 goal 检查过的同一证据和同一物理视角不再重复安排 REVISIT；真正的新证据允许重新进入。
3. 重访成本门控：沿用现有可达性、剩余步数和探索成本比较，不额外建立语义置信度重排器。
4. 持续意图：路线有效且可推进时保持 intent；源失效或恢复失败时释放。
5. 增量抢占：只由新实体或超过现有视角间距的新观察触发；同一证据不反复请求。

新增独立配置开关，旧阶段名和旧配置的策略含义保留；新实验配置明确列出开关值，并写入运行指纹。安全和正确性缺陷修复会改变受影响行为，需通过源码指纹与旧运行区分。

停滞检测默认连续 3 次执行未推进 waypoint，且到当前执行目标的已知路径距离未减少一个体素时触发恢复；旋转和明确的观察步骤不计入。距离比较限定在相同目标与可比较的路线状态，目标或路线重建后重新建立进展基准。

维持现有“一次局部修复加一次同终端重规划”上限，同一 intent 不逐帧重置恢复预算。

区分语义否定和运行错误：请求错误不得写入目标负证据，也不得永久封禁实体。失败处理服从请求预算；耗尽时明确记录错误状态。

统计每种任务的次数、路程、步数、调用量，以及重访是否产生新证据、抢占后是否形成有效 approach。先用这些统计定位无效开销，不新增猜测性的收益评分模型。

完成门槛：新增策略开关可独立关闭；关闭后恢复对应对照行为；固定证据不能造成重复重访或无限请求。关闭某项策略不能绕过已知空间运动和源有效性的必要约束。

### M4：完善 Verified，并分离成功口径

终点验证继续绑定同一实体、历史 crop 和新鲜 RGB。alias 迁移后仍需确认绑定一致。

沿用最多两次验证视角的现有预算，并要求第二次视角在物理位置上满足已有间距约束：

- `confirmed`：允许成功停止。
- `rejected`：更新当前 goal 与该证据的关联。
- `uncertain`：尝试新视角；无视角或预算耗尽则保留 unresolved。
- `error`：记运行错误，不生成负事实。

汇总中同时展示原有 Snapshot SR、Distance SR/SPL，并新增验证确认次数、确认后真实成功率、错误确认次数。后者仅在评测汇总中使用真值，不进入策略；同时注明实体匹配与距离成功的具体口径。

完成门槛：重复反馈、旧 intent 反馈、请求错误和不可用新视角均不能误触发成功停止。

## 三、离线测试与在线评测安排

### 离线回归

在现有测试基础上增加以下覆盖：

- 所有任务结束路径有明确原因，旧结果可读取。
- Baseline/Shadow 在固定输入、固定模型响应与 RNG 下，选择和动作不因旁路建图改变。
- 中间 waypoint 不触发任务完成；非 Verified 的 REVISIT 到达必须先在同一
  source-bound intent 内提升为 APPROACH，再落入原版 HGR 的 Snapshot 到达停止分支。
- 正确终端、错误实体和合理不可达能够分别归因。
- 三 goal 的地图与证据继承、目标状态隔离。
- alias、来源失效、证据去重、预算边界和停滞恢复。
- Verified 四类反馈与幂等处理。
- 每次实际执行调用均有对应运动事件，审计不会因缺少记录而误通过。

已有 Shadow replay 工具仅覆盖它实际检查的接口；完整等价性测试必须运行实际选择与执行适配路径，不能只比较原样返回的数据。旧 trace 无法提供完整回放输入时，明确报告覆盖不足，并为后续用户运行增加记录入口。

此前全量离线回归为 348 项通过；实施时重新确认当前测试基线，不将此历史结果当作新增修改已通过的证明。

### 运行与分析工具

扩展现有阶段执行入口，支持读取冻结实验矩阵、两个 manifest 分片和重复编号，默认串行运行并失败停止。

增加独立结果分析命令，输出：

- 七阶段及消融配置的指标表。
- 逐子任务失败原因与调用统计。
- 全局记忆增长、历史来源复用和重复访问。
- 运动记录完整性及证书审计。
- Markdown 报告和机器可读汇总。

脚本支持 dry-run；在线命令由用户执行。旧运行目录不覆盖，已存在完整结果可跳过，部分结果不得当作完整结果。跳过前核对源码、配置、manifest、分片及重复编号，不能只检查目录存在。

冻结内容包括源码指纹、解析后的有效配置、manifest 与校验值、模型标识与请求参数、步数预算、种子和重复编号。记录分阶段模型调用与重试，避免把网络重试误算为策略选择次数。

### 在线顺序与门槛

| 批次 | 内容 | 进入下一步条件 |
| --- | --- | --- |
| A | 已完成的三 goal 定向 smoke | 已覆盖 image/object、跨 goal 复用、拒绝、两视角确认与停止；不再补跑 8 goal |
| B | 取消完整重跑 | 旧 12×2 Baseline 仅作开发参考；Shadow 使用已有 smoke 与离线等价性测试；Route-only 并入 C-lite |
| C-lite | 3×2 清单的 Route-only、去重、成本门控、持续 Intent、Verified | 同一 6 episode 上完成机制筛选并冻结候选 |
| D | 独立 12×2 清单的 Baseline、Route-only 与冻结候选，各 3 次 | 只能在 C-lite 报告审阅和候选冻结后单独启动 |

总控脚本默认只运行 C-lite：5 个配置乘 6 个 episode，共 30 个 episode-stage。
它先运行离线回归，每项运行后检查结构化执行质量和已知空间运动记录，失败时
停止；重复执行相同命令会按完整指纹续跑或跳过。

```bash
export DASHSCOPE_API_KEY='你的 API Key'
python scripts/run_hgr_experiment_plan.py \
  --gpu 4 \
  --threads 16
```

只展开全部命令，不运行测试、simulator 或模型：

```bash
python scripts/run_hgr_experiment_plan.py --dry-run
```

C-lite 报告审阅后才冻结最终候选并单独运行 D，例如：

```bash
python scripts/run_hgr_experiment_plan.py \
  --phase final \
  --final-candidate verified-ablation \
  --gpu 4 \
  --threads 16
```

若未提供 `--final-candidate`，脚本拒绝启动 D。报告写入
`artifacts/hgr_rebuild/experiment_plan/`，开发和最终状态分别写入带
`development_state` 与 `final_state` 后缀的 JSON 文件。

若 C-lite 没有新机制通过候选门槛，使用 `--final-candidate route-only`。脚本会
自动去重，只在独立清单上运行 Baseline 与 Route-only 各三次。

Known-space 的失败修复先用固定输入回归和原 smoke 验证；若修改影响 Route-only 共用几何路径，批次 B 前必须重新跑 Route-only smoke。若批次 C 结果没有形成优于 Route-only 的候选，保留 Route-only，不强行发布完整机制版本。

12×2 开发清单位于 `cfg/manifests/goat_train_dev_12x2_seed77.json`。两个分片合计 24 个 episode，并非 24 个 goal；子任务总数由 manifest 对应数据实际确定。

主表报告完整样本；异常子集作为补充诊断，不从主表剔除。以场景为单位做配对汇总和 bootstrap，保留同场景多 goal 的相关性；同时报告逐场景胜负和目标类型结果。重复实验使用相同的一组种子，模型输出不能保证确定性，必须保留真实响应或可回放记录。

性能提升只有在目标成功指标的配对区间支持改善时才声明。区间跨零时结论为尚不确定。同等成功数下，候选版只有同时降低路程或模型调用且另一项不增加，才作为明确的效率改进。SR、SPL、路程与调用之间存在取舍时完整报告，不合成为未经验证的单一分数。

开发集用于选择配置；最终性能结论必须在未参与调参的清单上确认。最终清单在开发集迭代结束后单独冻结；未完成该确认前，报告统一标为开发集结果。

## 四、交付物与完成定义

最终交付：

1. 本计划文档，以及更新后的阶段能力说明。
2. 本轮失败逐子任务诊断报告，区分已确认原因和待验证假设。
3. 缺陷修复、机制开关与离线回归。
4. 可 dry-run 的冻结实验矩阵、用户运行脚本和结果分析入口。
5. 修复前后、逐项消融和重复评测报告。

开发交付与在线验收分别标记：M0–M4、运行矩阵、完成/指纹恢复、跨 goal 来源审计、JSON/Markdown 汇总和 scene-block 配对区间已经实现，离线回归通过；只有收到修复后在线结果并完成审计后，才能标记在线阶段通过。

本轮默认不开展跨 episode 长期记忆、模型训练、更换模型或大规模重写 runner。优先完成 **M0 → M1 → 原 smoke 重跑**，之后按 M2–M4 逐项推进，不把所有新机制合并成一次不可归因的性能实验。

## 五、C-lite 后续：自适应融合候选

C-lite 已完成并确认各机制不能全程累积开启：Memory-dedup 有小幅正向点估计，
持续 Intent 降低重选但增加长路线成本，全量 Verified 增加成功点估计但显著降低
SPL，成本门控则直接退化。基于这些结果，新增独立 `adaptive-hybrid` 候选：保留
去重记忆；Frontier intent 限制为 3 个实际运动步；只验证跨 goal 历史来源的
image/description REVISIT；关闭成本门控和增量抢占。完整实现与命令见
`docs/HGR_ADAPTIVE_HYBRID_IMPLEMENTATION.md`。

该候选先运行 `adaptive-screen`，与 Route-only、Memory-dedup 在同一清单上比较。
这是一项新的可归因筛选，不改写已完成 C-lite 的结论；只有 GOAT SR/SPL、成本和
机制审计共同通过后，才能把 `adaptive-hybrid` 冻结为批次 D 的最终候选。

首次单 scene、8 goal 的 `adaptive_hybrid_v1` smoke 已通过：Adaptive 的 GOAT
SR/SPL 为 87.50%/46.23%，Route-only 为 75.00%/44.83%，且 Adaptive 少 35 次
VLM 调用。选择性验证与三步 Frontier intent 均按设计触发，无运行错误。由于只有
一个 scene，该结果只允许进入 3×2 扩大样本筛选；详见
`docs/HGR_ADAPTIVE_HYBRID_SMOKE_RESULTS.md`。

3×2 扩大样本也已完成。Adaptive-hybrid 在 49 个 goal 上取得 77.55% GOAT SR 和
61.05% GOAT SPL，相对 Route-only 提高 12.24/10.27 个百分点，并减少 9.6% VLM
调用；代价是 Step 增加 37.4%、路程增加 22.7%，另有 4 个 exhausted。SR 配对区间
下界为零，SPL 区间跨零，因此当前实现冻结为批次 D 候选，不在开发集继续调参，也
不提前声明最终优于 Route-only。详见 `docs/HGR_ADAPTIVE_HYBRID_3X2_RESULTS.md`。
